# 固定ゲージを、腕のカメラで撮影・点検する

CRANE+の手先カメラで固定されたゲージを観測し、画像のずれに応じて関節1を補正します。撮影品質を満たした画像を採用した後、別の画像分類器で正常・異常に分類し、所定のhome姿勢へ戻ります。Gazebo上の単一ゲージの実証です。

- **対応動画（1分40.275秒）:** https://youtu.be/dGj1pyI_-Ps
- **技術説明PDF（42ページ）:** [説明資料_PAI最終課題_ykumakuma777.pdf](docs/説明資料_PAI最終課題_ykumakuma777.pdf)
- **再現手順:** [REPRODUCING.md](REPRODUCING.md)

動画の動作映像は一律2倍速です。手先画像は、その時点までに記録した最新受信画像を次の受信まで保持します。画像生成、時間補間、未来画像の先取りは行っていません。字幕・マークは録画後の編集注釈です。

## 2つのAI

|役割|入力|学習・出力|
|---|---|---|
|撮影位置を合わせる模倣モデル|ゲージ中心の左右ずれ [px] と現在の関節1角 [rad]|規則制御を教師としたbehavior cloning。標準化した2値をリッジ回帰へ入れ、関節1の角度差分を予測|
|画像を判定する分類モデル|採用画像を位置合わせ・切出し・白黒化・縮小し、HOGで作った8100特徴値|学習済み線形SVMでnormal／abnormalを分類|

HOGは輪郭の方向と強さを数値化する固定処理です。SVMがラベル付き画像から分類境界を学びます。初期観測姿勢への移動とhome復帰は固定動作で、模倣モデルが学んだ動作ではありません。

人が環境・配置・モデル・設定を準備し、実行コマンドを開始します。開始後に、人が補正方向・補正量を1回ずつ選ぶ構成ではありません。箱は試行開始前に配置を確定し、試行中は固定します。

## 学習データと分離

模倣モデルは左右×小・中・大の6学習配置、**11完了エピソードから17教師操作レコード**で学習しました。1エピソードは1回の点検全体、1操作レコードは操作前画像・実測関節角・教師差分・送信・到達・次の新画像が対応した補正1回です。12学習試行中の1停止は保存し、有効教師例に含めていません。

別の左右2配置の2試行・4操作だけで、事前候補λ=0.01／0.1／1.0から0.01を選びました。標準化と係数の計算は学習17操作だけです。最終評価の配置・画像・操作を学習や調整へ入れていません。

分類器の画像は、針角を設定した3DゲージをGazeboのカメラで撮影して作成しました。36画像ファイルを針角で学習24／検証12に分割し、学習画像だけを元画像＋小さな回転・移動・明るさ変化の3版にして96学習例としました。同じ角度の3ファイルは同じ画素内容で、学習8種類・検証4種類の画素内容です。96回の独立撮影ではありません。

## 動画の2事例

- **異常例:** ire4_repro_layout_20261031_01。今回の模倣モデルの呼出し2回・補正2回、撮影・異常分類・homeを確認した既知配置の再現記録です。最終評価6試行に加算していません。
- **正常例:** bc_eval_bc_eval_01_1_clone_bc15_20261029。初回から撮影条件を満たし、安定した画像から正常と分類しました。模倣モデルの呼出し0回・補正0回で、模倣補正の成功例には数えません。元記録と画像は examples/normal_classification/ に収録しています。

2事例は異なる制御モデル設定・配置の記録で、同一方策の正常／異常対照試験ではありません。画像分類器は同一の版・hashです。分類完了の正確な時刻は残っていないため、動画は「この試行の保存結果」として表示します。

## 安全と限界

関節1の1操作安全上限±0.055 rad、要求cap±0.0548 rad、補正しない関節2〜4の全計画点偏差0.002 rad、MoveItの衝突・経路検査、到達、排他、画像鮮度、home予算を維持しています。モデル出力の拒否、値の制限、全計画点検査は別の処理です。通信・controller・計画・到達異常では停止し、命令を自動再送しません。模倣方式から教師への自動切替もありません。

**実機・広い配置・照明への一般化、規則制御への優越性は未確認です。** 分類器の独立した画像別検証報告は再確認できず、汎化精度は主張しません。正常・異常はこの実験で設定した針位置の分類で、一般の計器の安全基準の判定ではありません。

完成範囲は単一ゲージの水平補正と画像分類です。上下・関節2の学習制御、強化学習、複数ゲージ統合、未知空間の自由探索は含めません。クリーン環境からのROS一式構築と動作再現は未検証です。実行済みID・過去の要求ログを再送して再現しようとせず、新しい動作には別の準備・現状診断・承認が必要です。
